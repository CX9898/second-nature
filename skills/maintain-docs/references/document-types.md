# 文档类型与改写判断

先选与目标文档有关的部分。下列内容是检查维度，不是每份文档必须补齐的章节模板。

## 职责与读者

| 类型 | 负责回答的问题 | 控制边界 |
| --- | --- | --- |
| 根 README | 项目是什么、适合谁、主要能力与入口在哪里 | 按项目约定保留最短使用路径，不堆放完整配置、逐文件清单和开发进度 |
| 用户指南与示例 | 有什么前提、如何运行、结果在哪里、怎样判断成功 | 必需条件提前说明，复杂步骤形成连续流程；简单例子无需重复七段说明 |
| 配置与 API 参考 | 字段或参数怎样影响行为 | 核对类型、默认值、优先级、加载时机、状态约束、错误及返回格式 |
| 构建与发布指南 | 维护者怎样构建、验证、生成和更新制品 | 保留必要的工具链和制品关系，区分内部构建与最终用户安装 |
| 架构 | 当前模块怎样协作、数据与制品怎样流动 | 描述已实现结构、接口、配置来源和有实际影响的约束 |
| ADR | 某项决策为什么成立、考虑过什么取舍 | 保留状态、时间、背景、决策和影响；新变化按项目约定修订或增加记录 |
| 算法与技术推导 | 计算如何定义、实现如何对应、误差怎样产生 | 保留符号、布局、公式、舍入与边界、实现对应和验证条件 |
| 目录 README | 这个目录放什么、稳定入口是什么 | 面向实际读者说明当前层级，不展开无关的解压后结构或描述 README 自身 |
| CHANGELOG | 某版本改变了什么、对使用和升级有什么影响 | 选择重要变化，区分产品与独立组件版本，保留正式历史 |
| 贡献指南 | 如何开发、测试、提交与维护 | 采用仓库真实入口和必要要求，不创造团队制度或审批角色 |

## 使用说明与可运行例子

依据读者的任务补足环境、执行目录、输入、命令、输出和成功条件。前提已由上文说明时可以引用，不必在每个代码块重新列出。

- 命令顺序中的目录、变量与输出应能衔接。区分示例占位路径、用户可配置路径和工具固定生成路径。
- 默认流程先说明真实默认行为；可选模式给出启用条件。不要让用户手工决定已由工具自动匹配的内容。
- 涉及模型、数据或实验质量时，区分接口冒烟输入和代表性正式数据。一次随机输入成功不证明生产精度或长期稳定性。
- 资源、硬件和兼容要求按实际支持范围说明，避免把某次测试机器写成唯一使用条件。
- 制品说明依据产物及其消费方：谁需要哪个文件、辅助文件是否可选、怎样加载或使用。不要假定所有发布都必须有 manifest、聚合校验清单或额外元数据。

## 配置参考

追踪配置从创建、加载、覆盖到执行的路径。需要时将下列值分别说明：

| 值的类别 | 核对位置 |
| --- | --- |
| 新实例的初始值 | 构造函数或数据类定义 |
| 配置缺省字段的加载值 | 解析器、合并器和 schema |
| 示例显式值 | 示例配置及其调用位置 |

还要核对匹配优先级、何时生效、未知字段和非法状态的处理，以及保存、重载、重新校准等操作的必要条件。只写当前接口实际存在的字段，不凭规范补出产品能力。

## 发布说明

先判断变化是否值得用户关注，再决定放入新增、变化、修复或升级说明等现有栏目。无需为每个版本增加空栏目。

- 修复说明以触发条件和用户可见结果为主。实现细节只有影响部署、使用或升级判断时才进入正文。
- 升级说明明确需要采取的操作、适用版本与兼容边界。不要在每次发布模板中重复已经结束的历史迁移事件。
- 不把重新构建、重新导出、重新安装或重建运行环境混写成同一件事，实际需要哪一步就说明哪一步。
- 更新指定版本时遵守用户给出的归档范围，不顺带提升其他组件版本或重写既有正式发布历史。

## 架构、ADR 与推导

架构文档与目标版本的模块、接口和数据流对应；图中名称、张量布局、位宽或中间产物与实现一致。沿用已有可维护图源，不为统一风格强制重画全部图。

ADR 的历史决策可以解释过去的约束。按新行为维护当前指南，并以修订、替代关系或新 ADR 说明决策变化；不要让历史记录看起来一直采用新方案。提案和未来工作需要明确实现状态，不能改写为已支持能力。

技术推导按其知识价值维护。通过术语定义、导航、引用和结构改善可读性；保留有效公式、适用条件、误差和实现关系，不以“用户视角”将其压缩成宣传摘要。

## 改写示例

### 从实现动作改为用户影响

过程描述：

> 为任意数值 UID 设置默认用户名和临时 HOME，补齐容器初始化变量。

用户可感知的修复：

> 修复以非 root 用户运行容器时，部分模型处理流程因用户名查询失败而中断的问题。

只有读者需要配置这些变量时，才在部署参考中保留变量名和覆盖方式。

### 从对话补充改为目录事实

过程描述：

> 根据之前的要求，本次删除了重复索引，并补充 JSON，方便后面继续核对环境。

目录文件说明：

> 同名 JSON 记录环境组件版本和依赖清单，供查询和问题排查使用。

这一变化是否进入 CHANGELOG，仍取决于它的用户影响；表达合适不代表必须公告。

### 简洁与准确的边界

保留“CPU 不支持 QAT”等真实限制。可以同时给出支持的替代路径，但不要通过删除否定句、弱化精度条件或删掉推导来制造“更好读”的假象。
