# 文案边界对照

用于配置、操作指南和接口参考的表达审查。以下是假想工具的行为契约，不是本仓库的真实接口。各例中的技术陈述均正确，相关概念属于同一流程，读者有领域基础；判断差异来自当前位置的任务、信息增量及实际入口，而非术语数量或句式。

每例先固定读者问题和行为，再比较原文、处理结果与保留对照。将判断方法用于实际材料，不把例子中的参数名或“默认”“本例未设置”等词当作删除信号。

## 一、选项存在，但不属于当前配置任务

**契约与读者任务**：导出 SDK 真实支持 `initial_compression`。入门模板有意只展示筛选条件和输出路径，用户正在确认“改筛选后，已有文件是否更新”。产物格式另有现成参考，后续压缩步骤有自己的条件与调用说明。

**原文**：

> 修改筛选条件后需要重新导出，已有文件不会自动更新。本模板不设置初始压缩模式，新建导出器默认生成未压缩文件，本例在发布流程中选择压缩。

**处理**：本段保留前一句。后面的构造默认值有独立格式知识价值，可由已有输出参考承接；“模板不设置什么”和笼统的公共流程说明无需在这里重述。改成更短的“初始模式由流程控制”仍没有帮助当前选择。

**依据**：移走后，用户仍能准确判断配置何时生效。当前配置没有这项展示，额外提及会让读者寻找另一个设置入口；它属于同一导出功能，也不因此成为此处的必要前提。

**保留对照**：用户正在将产物交给只接受 gzip 的接收方时，输出未压缩及如何转换直接影响使用，应在输出格式或压缩步骤说明。已有用户在查示例入口变更时，“模板不再展示该设置、SDK 能力保留”也可能是必要兼容说明。不能将这些事实从整个文档体系删除。

## 二、真实机制插入了连续的生命周期说明

**契约与读者任务**：工具负责生成 JSON 清单；签名覆盖最终清单的实际字节，发布必须使用同一版本清单与签名。当前用户调用现有命令，需要理解哪些修改使旧签名失效，并不实现序列化或读取器。

**原文**：

> 清单改动后须重新签名，旧签名不再适用。生成器默认写 JSON，读取器使用流式解码。发布时使用本次生成的清单及其对应签名。

**处理**：移走中间两项机制说明，合并为“清单改动后重新签名，发布时使用该清单及其对应签名”。格式和读取机制在已有格式参考中保留，不为安置每句话新建章节。

**依据**：本段的关系是“变更使旧状态失效 → 重建对应状态 → 后续消费同一版本”。插入内容虽然描述同一产物，却没有解释这一状态关系；删去后主线完整、前后衔接更直接。

**保留对照**：“签名覆盖实际字节，所以仅改变空白或字段顺序也要重新签名”应保留，它明确了哪些修改会失效。读者在实现签名或读取器时，编码、序列化顺序和解码规则则可能就是当前主题，不能因其属于内部机制而压缩掉。

## 三、相邻重述与有用途的重复

**契约与读者任务**：同一篇指南按“创建归档 → 校验归档”连续阅读。校验章节已经完整提供命令、密码条件、成功与失败信号和结论边界，创建章节没有独立交付或跳读入口。

**原文布局**：

> 创建节末：加密归档校验需要相同密码；返回 0 并显示 Verified 表示通过，但不证明源目录中的所有预期文件均已纳入。
>
> 紧接的校验节：运行校验命令……加密归档需要相同密码；返回 0 并显示 Verified 表示通过，但不证明源目录中的所有预期文件均已纳入。

**处理**：完整条件集中保留在校验章节。创建结尾可只写“创建完成后按下一节校验”，或自然结束，不提前复制整段。

**依据**：后一节就在阅读路径上，重复段没有新增分支、条件或当前风险防护，反而让人辨别是否有两套要求。不能因为两段分别都正确，就认定排列没有问题。

**保留对照**：独立交付的离线 README 没有上文，需重述运行前提；不可逆覆盖命令前的简短提醒，即使上文出现过，也在风险动作处提供保护。重复有价值时保留对应内容，不按次数机械去重。

## 四、构造默认值不是当前入口的操作前提

**契约与读者任务**：解析器构造默认 `schema="v2"`。CLI 导入入口会先读文件头，再选择 v1/v2 解析器，两个版本都支持；CLI 不展示构造参数。用户正在执行导入，不直接构造解析器。前文已给出支持范围、导入命令和结果检查。

**原文**：

> CLI 支持 v1、v2 文件并自动识别。运行导入命令，核对记录数及错误报告。本模板未设置解析模式，解析器构造默认采用 v2；入口的模式由公共加载流程按文件头选择。

**处理**：保留文档中已有的入口实际支持、命令及结果判断，由前文承接即可，不再重复；删去末尾的初始化与模板省略说明，构造默认值由 SDK 参考承接。

**依据**：入口已经自动选择，初始化默认值不改变用户应给什么输入或如何调用。仅少知道一条构造事实，不等于用户对当前导入任务的理解缺失；重述内部选择还可能让人误以为要手工配置版本。

**保留对照**：直接使用 SDK 构造解析器时，默认 v2 和处理 v1 所需参数必须说明。若某入口只接受 v2，或不会自动满足前提，则导入前必须明确输入约束。默认值、实际生效行为与必要输入状态要分开核对，不能将所有初始化说明都删掉。

## 在实际审查中应用

对可疑说明，指出它在同一位置改变了哪项理解、选择、条件、风险或结果判断。对照前后文和可用的中性 diff，判断应保留、就地解释、迁移、合并还是删除。输出具体位置、原文、影响及建议，不只贴“冗余”标签。

同一类信息在另一个入口或任务中可能必要。换用其他术语或句式后，判断仍应依据任务作用；技术错误不是编辑建议成立的前提，文本更短也不是唯一目标。必要的专业知识、生命周期限制、结果保证与风险提醒应继续保留。
